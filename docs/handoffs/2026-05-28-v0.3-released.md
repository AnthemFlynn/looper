## Part 1 — For the senior dev (the *why*)

### TL;DR
v0.3 observability is **shipped to `main`** (release PR #43). Along the way we found and fixed a real cross-build break in v0.2 that had been sitting red.

### Decisions made (and why)
- **Fixed a v0.2 cross-build break before merging anything.** `exec.zig`'s `sleepNs` instantiated `c.struct_timespec` by value; musl/cross SDKs make that type *opaque*, so all three ReleaseSafe cross-targets failed. The native `test` CI jobs only build debug, so they were green and it slipped through. Fix: declare an explicit `extern struct { tv_sec: c.time_t; tv_nsec: c_long }` and pass it through the opaque pointer (`stdlib nanosleep`/`Thread.sleep` don't exist in this Zig 0.16). Rationale: cross-compilation is first-class per CLAUDE.md; never merge a red build.
- **Stacked PRs merged with merge-commits, not squash.** #37 (agenda) was stacked on the unmerged #26 (v0.2). Merge-commits preserve the exact SHAs so the stacked branch stays clean on retarget; squash would have orphaned the SHAs and made the diff messy.
- **Two-trunk workflow + default branch → `dev`.** Per your request. CI triggers extended to `dev` (push + PR) so PRs into `dev` get the full matrix — closes the gap that let #37 reach a merge decision with *no* checks.
- **`diff` MVP = foreign-line detection only.** The richer `~`/`-` (managed job changed/removed externally) categories from #10 need a stored per-job expectation looper doesn't persist yet — deferred to **#39**. Foreign-line presence is the drift signal detectable from the crontab alone.
- **`verify` semantics: "unknown" is never a failure.** Overall `ok` = no check *failed*; a check we can't run (privilege boundary, unparseable command, unprobeable target) is surfaced as `unknown` but doesn't flip `ok`. This avoids both false confidence and false alarms — the explicit requirement in #7.

### Risks & landmines
- **The timespec class of bug.** Any by-value libc struct that's opaque under musl will break cross-builds while passing native tests. Mitigation is procedural: the `build` matrix is the real gate — treat a red `build` job as blocking even when `test` is green. Now documented in CONTRIBUTING.
